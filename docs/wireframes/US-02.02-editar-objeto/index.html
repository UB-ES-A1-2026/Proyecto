  1. Lleva al formulario de publicar (/objetos/nuevo).
  2. Filtros por estado con el número de objetos de cada uno. Si un filtro no tiene ninguno: «No tienes objetos en este estado.».
  3. Criterio 1: cada objeto publicado o pausado tiene su botón «Editar», que abre la ventana. La fila enseña la primera foto o, sin fotos, un icono.
  4. Los retirados no tienen botones: retirar es definitivo y la API respondería 409 (#202).

InicioMis objetosMis solicitudesMi perfil
  1. Ventana sobre la lista. «×», «Cancelar», la tecla Esc o un clic fuera la cierran sin guardar. Mientras carga el objeto se ven campos de relleno. Si no se puede cargar, sale el error y «Cerrar».
  2. Criterio 2: llega con los datos actuales. El cuerpo de la ventana hace scroll y la cabecera y los botones se quedan fijos; en el móvil se ve hasta «Añadir fotografías» y las miniaturas quedan más abajo. La disponibilidad se cambia con «Pausar» y «Reanudar» en la lista (US-02.04).
  3. Se pulsa o se sueltan encima las fotos. Sin fotos: «Tiene 0 de 5 fotos.» y no hay miniaturas. Con otro tipo de archivo o más de 5 en total: «El campo "fotografías" no es correcto, revísalo.».
  4. Las fotos nuevas se pueden quitar antes de guardar. Las que ya tiene no se pueden borrar (queda para el Sprint 2).
  5. Al pulsar se valida todo a la vez. Mientras se guarda, el botón dice «Guardando…» y está desactivado.

  1. Criterio 4: el error sale debajo de su campo y el foco va al primero. Mismas reglas que el backend: nombre de 1 a 100 caracteres, descripción de 1 a 2000, precio mayor que 0 y fianza de 0 o más.

  3. No se guarda nada y el error desaparece al editar el campo. Otros errores de la API salen como aviso arriba de la ventana: «Solo el propietario puede editar este objeto.», «No se puede editar un objeto retirado.» o «No hemos encontrado este objeto.».
